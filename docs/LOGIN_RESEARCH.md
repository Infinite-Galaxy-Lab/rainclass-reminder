## 公众号场景登录补充

官方 `/authorize/login` 的 chunk `68520.67ed8b9b.js`、模块 `91842` 是 `login-qr` 组件。
它消费 `pre-info` 返回的图片与令牌，以同一令牌发起 `POST /api/v3/user/login`，前端超时为 70.2 秒。
返回体 `code === 0` 后再请求 `basic-info`；换码会取消旧等待请求。该端点只用于认证，不属于业务抓取层。

匿名响应确认：`pre-info` 的二维码内容来自 `weixin.qq.com/q/`，图片来自公众号二维码接口；
`app-web-pre-info` 的二维码内容则指向本站 `app-web-qr`。两者也不能与 alpha.8 的微信确认链接混用。
匿名打开前两类内容未取得有效登录页面；这不代表真实微信内的打开结果已经被验证。

官方通用请求封装在响应含 `set-auth` 时缓存该值，随后发送 Bearer 认证。
这是条件处理代码，不能证明该登录接口的成功响应一定带此头，也不能证明服务器没有同时设置 Cookie。
当前 App 走 Cookie 身份校验；在实际成功响应尚未观察前，不新增 Bearer 存储或把两种认证方式视作等价。
`/authorize/callback` 的对应组件处理腾讯会议 `auth_code`，不是公众号登录结果交回本 App 的证据。

本机匿名诊断工具已保存在仓库外，可重复检查以上三个官方入口，只保存状态、固定路径、参数名等元数据。
两项合成隐私回归覆盖场景链接与 OAuth 查询内容，均实际破坏脱敏取得断言红后恢复绿；
未保存真实二维码内容、OAuth state、令牌、Cookie 或授权码。该工具不测试微信接受性，也不获取已登录会话。

## 网页 OAuth 回调边界

2026-11-09 追加匿名探针：`/login/weixinapp/` 返回 302，并先下发 sessionid；
重定向是 `snsapi_userinfo` 网页 OAuth，回调仍是官方 `/complete/weixinapp/`。
未带授权码、以及只带合成无效 code/state 的回调均返回 HTTP 400，JSON errorcode 为 500，errormsg 为空。
这是匿名错误响应，不能证明 state 的校验顺序、授权码是否已兑换或成功会话能否迁移。

SicnuJw 截图中的手工粘贴回调 / code 思路尚缺雨课堂自身的接收协议证据。
不能直接实现“复制微信地址回 App”并声称可用，也不能把同一浏览器登录成功视为原生客户端已认证。
匿名探针只输出固定路径、状态、Cookie 名和参数名；不保存 state、Cookie 值或二维码内容。

后续匿名比较发现，同一 Cookie 上下文重复获取的 OAuth state 相同；两个独立 Cookie 上下文的 state 不同。
这一组样本显示 state 与原匿名会话有关，仍未证明服务端接受从微信手工复制的回调 / code。
公开前端的公众号场景组件无参数请求 `pre-info`，随后只提交 `{token}` 等待；
独立 `/wx-qrlogin` 和共享错误跳转 `/login/weixinapp/` 都没有携带该 token 的可见数据流。

## 官方 App 扫码入口

公开登录源码的 `app-web-pre-info` 无请求参数，返回 `qrContent` 和等待令牌。
页面只把内容绘制成二维码，并向 `/api/v3/user/login/app-web-login` 提交 `{token}` 等待，
前端超时为 180 秒。二维码内容指向官方 `/api/v3/user/login/app-web-qr`，查询键为 `u,t,s,v`。

本轮使用各自全新的匿名二维码，分别以普通浏览器、微信 UA 及浏览器导航头访问该地址，
均返回 HTTP 404，未带跳转地址。先启动匿名等待再访问二维码地址，仍为 404，随后中止等待。
未观察到 OAuth 跳转或等待端收到结果；未使用用户截图的真实会话。

这不证明该入口在官方 App 扫描器内部也不可用，也不能断言 404 是路由缺失或权限校验所致。
当前公开静态资源与匿名浏览器访问均未提供可接入本应用的网页授权桥接。

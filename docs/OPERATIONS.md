## 回退

先停止目标计划任务并确认其子进程已退出；不要同时运行两个数据库写入者。若原任务本身已指向失效路径，应改用保留的上一版二进制和设置，不盲目恢复失效配置。

可用备份的 XML 恢复任务：

```powershell
$xml = Get-Content -LiteralPath '<私有备份目录>\task.xml' -Raw
Register-ScheduledTask -TaskName '<原任务名>' -Xml $xml -Force
```

还原同一备份中的 `settings.json` 与启动器，核对二进制存在、配置/数据路径一致，再选择登录或手动启动。只替换二进制不等于数据库可降级；将来出现不兼容迁移时，必须恢复配套数据库备份。

## 运行数据备份

当前没有上线热备份命令。最安全的手动方式是在维护窗口停服务，确认数据库关闭后，将配置、`cookie.json`、整个数据目录和版本/哈希记录复制到仓库外私有备份。优先使用加密存储，凭据与可公开源码不要混装。

运行中的 SQLite 不能只复制 `state.db`，WAL 中可能仍有未合并事务。需要不停机备份时先实现并验证 SQLite online backup API，再增加定期备份任务；本轮未对运行数据库做不一致的文件拷贝。

恢复演练使用隔离目录与合成凭据，检查任务数、推送去重记录和 schema。正式恢复后先核对路径，再恢复自动运行，防止因空库重置造成历史提醒重复。

## 交接内容

交接者只需先读 HANDOFF；里面应记录当前代码/CI状态、运行进程是否更新、任务名与启动日期、尚未取得的证据和下一步验证。不要记录真实账号、课程成绩、cookie、Webhook 或 API key。签名密钥只用发行环境秘密存储；丢失 Android 签名密钥会影响后续升级，正式发行前必须建立加密备份与恢复流程。

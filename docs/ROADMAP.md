|---|---|---|---|

| P2 工具 | 被动观察、脱敏报告、登录自启 | 不增加业务请求；重启不延长 24h 抓取；假数据与启动器验证 | 桌面 11-09 11:06:36 起观察 24h；网页 11:48 确认实际记录，下次登录自启仍待验 |

## 下一轮维护顺序

1. 核对两路观察结果与关机造成的空档，不把不足 24h 的记录当全天结论。
2. 修复数字课件类型兜底与详情失败组合；补“Vault 保存成功、SQLite 后续失败”的当前进程恢复及学习日志缓存清理回归。每项独立提交并实际反向验证。
3. 取证真实开课任务与“课堂”录播的区别，再决定 `TaskClass` 映射；不按标题或标签强行提升。
4. 真机先复验切微信后台扫码返回、登录后自动同步，再验 Cookie 失效去重告警、通知拒绝后重试、重登恢复；随后做重启 / Doze / 厂商省电和断网恢复。系统回收进程后的未完成二维码和认证中返回的取消时序仍待验。
5. API 26、arm64、16 KiB 页设备、密钥跨机恢复与正式发行；Windows Wails 仍未开始。

## 合并与发布

- 功能分支使用 `codex/` 前缀，围绕一个可验收结果提交；正常提交经全量验证推入 main。
- 合入 main 不等于创建发行版；只有平台验收、升级/回滚和材料齐备后打版本标签。
- 变更端点、解析器、数据库或提醒策略时更新 API_NOTES / ARCHITECTURE；每轮结束更新 HANDOFF 与此表。
- 新增回归必须实际破坏对应实现取得断言失败，再恢复全绿；编译失败不算。真实账号材料保持仓库外，不把其内容复制进测试。

# ADR 0002：Android 原生持有微信扫码任务

状态：已实现；补齐微信轮询 `last` 后，用户已确认 MuMu 后台扫码返回成功。真机单手机登录另行验证。日期：2026-11-09。

## 依据

alpha.6 的 Cookie 检查无法修复后台扫码：用户在微信确认成功，返回仍停在登录页。
标准 MAIN/LAUNCHER 启动、单个 WebView 下仍复现。官方默认 App 扫码确认请求等待
180 秒后被取消，未取得 sessionid；一次同 token 恢复实验也未取得结果。
这些证据不能解释服务端内部状态，但足以说明只轮询 Cookie 无法补齐缺失的登录结果。

## 决定

Android 默认显示原生二维码，复用 `internal/auth.QRLogin` 已有的微信 OAuth 流程。
`internal/application.Login` 持有独立 Cookie jar、五分钟上下文和两秒轮询；绑定导出
图片、等待结果和取消；alpha.8 另提供当前二维码等价的官方确认链接供调试实验，
不导出微信 state 或 Cookie。该链接只在未取消、未过期且仍待确认的会话中可读取。认证接口没有复制到 Kotlin。

`LoginViewModel` 持有一次登录任务。切后台保留任务，重建页面复用 ViewModel；
退出或换码取消旧任务，协程取消后检查活动状态，避免旧结果覆盖新二维码。
返回前台后才交付 Activity Result，首页沿用现有的登录成功立即同步逻辑。

扫码得到的 Cookie 仍须交给 `Mobile.Authenticate` 校验非零身份，再保存到 Keystore
支持的密文存储。二维码和 OAuth 临时状态不持久化，不写日志。
业务抓取继续只有 GET，认证沿用既有协议，不增加作业提交、答题或交卷接口。

官方网页登录保留为显式备用入口，不改变其域名白名单。

## 边界

不引入前台服务、常驻通知或电池豁免。系统回收未完成的登录进程后重新获取二维码；
不能据此承诺 Doze、厂商省电或断网期间仍能即时完成认证。
合成测试覆盖 Home 后从启动器返回；实际微信确认、回调和手机省电仍需分别验收。

## 单手机实验与原生授权边界

用户要求无 root 且只用一部手机。微信在实机拒绝从相册识别此登录码，
允许应用截图无法解决微信自身的识别限制。Live-QR 负责摄像头解码和外部屏幕重绘，
仍需第二块屏幕，不满足这一需求。

alpha.8 的“单手机登录实验”仅在调试/验证包显示。用户主动复制官方确认链接后，
可在微信文件传输助手发送给自己并点开；原有 Go 轮询、身份校验与加密存储不变。
复制标记为敏感剪贴板；换码、结束或回到前台发现失败时只清除本入口留下的内容，
不覆盖用户后来复制的其他文本。用户随后真机反馈仍要求扫码或提示不允许，实验失败。
用户提供的微生活绑定截图走学校网页 OAuth 授权，雨课堂也有对应类型的官方入口；
会话如何交回 Android 尚缺证据，不能替换 URL 后宣称可用。取证与源码范围见 [LOGIN_RESEARCH](../LOGIN_RESEARCH.md)。

微信 OpenSDK 原生登录需要审核通过的移动应用 AppID、包名和签名配置，
网站扫码的 `snsapi_login` 不构成该资质。即便注册本项目的移动应用，
也仍需雨课堂支持对应 code 到其会话的转换，不能直接当作已登录雨课堂。
因此不在发行版加入未验证的“一键微信授权”按钮。参考与后续验收见 ANDROID。

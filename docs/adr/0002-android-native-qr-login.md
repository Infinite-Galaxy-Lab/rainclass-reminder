# ADR 0002：Android 原生持有微信扫码任务

状态：已实现，真实后台扫码复验仍失败，继续取证。日期：2026-11-09。

## 依据

alpha.6 的 Cookie 检查无法修复后台扫码：用户在微信确认成功，返回仍停在登录页。
标准 MAIN/LAUNCHER 启动、单个 WebView 下仍复现。官方默认 App 扫码确认请求等待
180 秒后被取消，未取得 sessionid；一次同 token 恢复实验也未取得结果。
这些证据不能解释服务端内部状态，但足以说明只轮询 Cookie 无法补齐缺失的登录结果。

## 决定

Android 默认显示原生二维码，复用 `internal/auth.QRLogin` 已有的微信 OAuth 流程。
`internal/application.Login` 持有独立 Cookie jar、五分钟上下文和两秒轮询；绑定只导出
图片、等待结果和取消，不导出微信 state 或二维码标识。认证接口没有复制到 Kotlin。

`LoginViewModel` 持有一次登录任务。切后台保留任务，重建页面复用 ViewModel；
退出或换码取消旧任务，协程取消后检查活动状态，避免旧结果覆盖新二维码。
返回前台后才交付 Activity Result，首页沿用现有的登录成功立即同步逻辑。

扫码得到的 Cookie 仍须交给 `Mobile.Authenticate` 校验非零身份，再保存到 Keystore
支持的密文存储。二维码和 OAuth 临时状态不持久化，不写日志。
业务抓取继续只有 GET，认证沿用既有协议，不增加作业提交、答题或交卷接口。

官方网页登录保留为显式备用入口，不改变其域名白名单。

## 边界

不引入前台服务、常驻通知或电池豁免。系统回收未完成的登录进程后重新获取二维码；
不能据此承诺 Doze、厂商省电或断网期间仍能即时完成认证。
合成测试覆盖 Home 后从启动器返回；实际微信确认、回调和手机省电仍需分别验收。
